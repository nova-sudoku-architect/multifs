# MultiFS Enhancements — Proposal (2026-08-21)

Five enhancements. (Original request numbered them 1, 2, 4; two more added 2026-08-21
afternoon as items 3 and 5.)

- **1** Folder "size" = number of direct children, shown on the web list/preview page.
- **2** Symlinked folders (tag folders) — link videos into tag folders; safe delete.
- **3** Prev/next navigation — slide between folders.
- **4** fsck removes broken symlinks (target no longer exists).
- **5** Folder preview page — cover images → preview GIF → video summary.

## Feature 1 — Folder child count (web list/preview page)

Semantics: **direct child count** = number of immediate sub-folders + immediate
files under a prefix. (Recursive count is out of scope unless William asks.)

### DB
Add to `src/storage/metadata.rs`:

```rust
pub fn count_direct_children(&self, bucket: &str, prefix: &str) -> anyhow::Result<i64>
```

SQL (prefix `P` normalized to end with `/`; pattern `P%`):
- immediate files: keys `LIKE 'P%'` whose suffix after `P` contains no `/`
  (and exclude any zero-byte folder-marker keys that end in `/`).
- immediate subfolders: `COUNT(DISTINCT <first segment after P>)` over keys
  `LIKE 'P%'` whose suffix contains a `/`.
- return files + subfolders.

Index note: `files(bucket_name)` already has `idx_files_bucket`; for large trees
a `GLOB`/prefix scan is fine at current scale (~hundreds of objects). No new index
required now.

### Web
In `src/server/web/mod.rs` `list_objects` handler: for each returned prefix, call
`count_direct_children` and add `"child_count": n` to the prefix JSON.

In `src/server/web/index.html`: render a small `n items` badge on each folder card
(and optionally in the folder detail header).

S3: **not** changed — S3 has no folder-size concept (this is a UI-only feature).

## Feature 2 — Symlinked folders (tag folders)

Goal: create tag folders (e.g. `tags/口交/`) and link videos into them, so the same
video appears under multiple tags without duplicating bytes. Symlinked folders must
behave like normal folders over the S3 protocol; deleting a symlink must NOT delete
the target; recursive deletion must **stop** at a symlink.

### Schema
New table (migration bump `schema_version`):

```sql
CREATE TABLE IF NOT EXISTS symlinks (
    bucket_name  TEXT NOT NULL,
    key          TEXT NOT NULL,          -- link path (e.g. 'tags/kiss/blor-116')
    target_bucket TEXT NOT NULL,
    target_key   TEXT NOT NULL,          -- real object/folder path
    created_at   INTEGER NOT NULL,
    PRIMARY KEY (bucket_name, key)
);
CREATE INDEX IF NOT EXISTS idx_symlinks_bucket ON symlinks(bucket_name);
```

A symlink points at a **folder prefix** (link `key` acts as a directory) — this is
the primary use case (tag → folder). Pointing at a single object is a later option.

**v1 constraints** (decided 2026-08-21):
- `target_bucket` MUST equal `bucket_name` (**same-bucket only**). The column is
  kept so cross-bucket can be enabled later without a migration.
- Targets are **folder prefixes only** (no single-object links yet).
- **Write via link is NOT supported**: a PUT/DELETE on a link path must never be
  treated as targeting the real object — it only affects the symlink record.

### Metadata API (src/storage/metadata.rs)
- `create_symlink(bucket, key, target_bucket, target_key)`
- `delete_symlink(bucket, key)`
- `list_symlinks_under(bucket, prefix) -> Vec<(key, target_bucket, target_key)>`
- `resolve_symlink(bucket, key_or_prefix) -> Option<(target_bucket, target_key)>`
  (exact match; then, if not a direct match, resolve the longest ancestor symlink
  prefix — for nested tags)
- `list_all_symlinks() -> Vec<...>` (for fsck)

### Listing resolution (the core of "works like a folder on S3")
- `src/server/s3/mod.rs` `list_objects` and `src/server/web/mod.rs` `/api/list`:
  1. If the requested `prefix` (or an ancestor of it) is a symlink, resolve to the
     target prefix and list the **target's** children, re-presented under the link
     path.
  2. Otherwise, after grouping real objects, also query `symlinks` whose `key` is
     directly under `prefix` and merge each into `CommonPrefixes` so a symlinked
     folder shows up as a normal folder.
- Add a `resolve_symlink_prefix(bucket, prefix)` helper (depth-capped, e.g. max 8
  hops) to prevent symlink loops.

### Deletion semantics
- `DeleteObject` / `DeleteObjects` on a symlink `key`: delete the `symlinks` row
  only; never touch the target.
- Recursive delete (DeleteObjects with a folder prefix; or any internal recursive
  walk): when the walk reaches a symlink, delete the symlink row and **do not
  descend** into its target. Symlink targets are never traversed for deletion.
- `delete_bucket` / `delete_all_objects`: must also clear `symlinks` for that bucket.

### CLI (src/cli/link_cmd.rs, wired in cli/mod.rs + main.rs)
- `multifs link <bucket>/<key> <bucket>/<target_key>` — create
- `multifs unlink <bucket>/<key>` — remove
- `multifs list-links [--bucket B]` — list

(S3 protocol has no symlink verb, so creation is CLI-only. Optionally accept a
magic header on PUT later.)

### get/head through a symlink (phase 2)
`head_object` / `get_object_stream` on a link key resolve to the target, so a video
can be downloaded via its tag link. **Deferred to a 2nd pass.** Write-through-link
is explicitly **not** supported (see constraints above). The `resolve_symlink`
helper makes read-through cheap to add later.

## Feature 3 — Prev/next navigation (sliding folders)

Goal: add **prev/next buttons** to navigate between folders instead of going back
to the list grid every time.

Resolved decisions (William, 2026-08-21):
- Scope: **sibling folders only** (same parent).
- Placement: **top bar on the preview page**.
- Interaction: **plain prev/next links** (no CSS slide animation).

## Feature 4 — fsck removes broken symlinks

In `src/cli/fsck_cmd.rs` add a new step (insert after `[1/5]` DB integrity, or as
`[6/5]`; renumber to keep it tidy):

- `meta.list_all_symlinks()`; for each, check target exists: `meta.get_object(target_bucket, target_key)` is `Some` **or** at least one object exists under `target_key` (folder target).
- Missing target → print `❌ broken symlink <bucket>/<key> -> <target>`; increment `problems`.
- With `--fix`: `meta.delete_symlink(bucket, key)`; report removed count.
- Dry-run by default (consistent with existing fsck behavior).

## Feature 5 — Folder preview page

Goal: a dedicated per-video/folder detail page that shows, in order:

1. **Cover image** (one per folder).
2. **Preview animation GIF** (one per folder).
3. **Video summary** (one per folder — title/plot/actors/tags/rating).

This surfaces the video-subtitle pipeline artifacts (cover, preview GIF, summary)
directly in the web UI, rather than just a thumbnail gallery.

Resolved decisions (William, 2026-08-21):
- Exactly **one** cover image and **one** GIF animation per folder.
- If a file is missing, **skip it** in the page (graceful degrade).
- Exactly **one** summary per folder; if absent, skip it.
- The **filenames** of summary / cover / GIF are stored in **folder metadata**
  (not hardcoded conventions). `folder_meta` gains columns (or a separate
  per-folder metadata table) for `summary_key`, `cover_key`, `preview_gif_key`.
- **Migration job**: once MultiFS is enhanced, run a one-off scan over existing
  folders to backfill these metadata fields from the files already present.
- **Pipeline integration**: the video-subtitle upload step must be enhanced to
  (a) create the folder and (b) write these metadata fields on upload.
  (This is a nova-video change, coordinated separately.)
